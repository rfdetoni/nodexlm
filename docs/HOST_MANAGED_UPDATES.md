# Host-managed Guest updates

Released desktop Hosts enforce their exact source commit for every RPC tunnel and whole-model job. An authenticated Guest receives a typed update directive, containing only an expected revision and version. No command strings, credentials or remote URLs are accepted. The coordinator excludes mismatches from placement and leases. Development binaries lacking a release identity do not enable this policy.

Desktop Guests download the official release for their OS/architecture, verify the GitHub SHA-256 and size, check the embedded commit and version, and replace their existing executable. The native worker is stopped before updating; saved pairing is preserved. If the artifact is not yet published, the Guest retries. Read-only system installations or Windows file locks may require the native package manager. Downgrades and automatic stable-to-edge channel switches are forbidden.

Android Guests obtain the official permanently signed APK from the existing public beta feed, verify the SHA-256, signing certificate, increasing versionCode and signed manifest source commit. An idle Guest requests installation through PackageInstaller. Android 12+ may allow self-update without confirmation when the system's conditions are met; Android 10/11 and other policy cases require system confirmation. Missing install permission or a legacy signing identity requires user action. A notification surfaces the confirmation.

Both pipelines now build from the same main source revision when desktop/application code changes. This deliberately spends an Android build on a desktop code change to preserve strict compatibility; native compiler caching remains enabled. Initial installation of this update-aware version is required on existing old Guests; older builds cannot execute a command they do not implement. Host-managed deployment does not automatically install arbitrary external runtimes or enable unvalidated Trellis tensor RPC.

The Android package-replaced receiver attempts to resume the previously active RPC or whole-model worker using the original pairing and resource policy. If Android blocks background foreground-service startup, the user receives a notification and reopening the app resumes the worker. Manual STOP cancels the pending resume. Update submissions use a cooldown to avoid repeated installation prompts.

Release Hosts admit stock RPC workers only when the advertised native source commit and all three protocol version components match the pinned bundle. Development builds still permit missing legacy metadata, but reject explicit mismatches. The native HELLO probe is still required. The desktop updater retains the previous executable on disk and reports its path if a failed replacement cannot be restored; pairing data is untouched.

New compute admission uses reported mobile telemetry: Android thermal status severe or higher (3+) or battery at or below 15% while explicitly not charging excludes a node from new RPC placements and whole-model leases. Missing telemetry is not interpreted as overheating or low battery. Existing in-flight inference is not forcibly interrupted by this policy. Recovery is automatic when subsequent telemetry clears the threshold. The dashboard reports the exclusion reason.

### Signed runtime policy

A released Host includes a short-lived Ed25519-signed policy in authenticated RPC heartbeats. It binds the intended stock native source, wire ABI, published archive digests, Host build, cluster epoch and individual Guest identity. Desktop RPC Guests verify it before provisioning, against the authority saved at pairing and the compiled-in reviewed release catalog. A signed policy cannot authorize a new download URL, source revision or executable. This is cluster authorization, not an upstream publisher signature; release archives still use the existing pinned SHA-256 verification. Android verifies the signed policy before starting native RPC and on authenticated heartbeats; APK updates retain their separate publisher-signature checks. Trellis policy activation requires a separate validated native adapter and is not enabled here.

Android 10+ uses the Bouncy Castle lightweight Ed25519 verifier without registering a replacement JCA provider. The Go envelope includes the exact signed payload bytes (base64 in JSON) so Android does not need to reproduce Go JSON escaping or map ordering. Previously paired Android installations that lack a stored authority may establish it once over their existing certificate-pinned authenticated connection; subsequent changes to the key, cluster or epoch are rejected. New enrollments store the authority immediately. This does not yet enable Trellis JNI or automatic switching to other native runtimes.

### Placement recovery

Automatic primary loads retry at most twice after an identified RPC preflight or relay-loss failure. Failed Guests are excluded only for that attempt series; unrelated native/model errors are not blindly retried. A subsequent inference request checks for a confirmed native process exit or loss of a previously established RPC session before emitting response bytes, and reloads the primary model using fresh placement. In-flight streams are not replayed, and no KV state is claimed to survive the failure.

Desktop updates now keep the previous executable until the replacement has been admitted through an authenticated RPC CONNECT or an accepted whole-model lease. A failed startup/early exit or 75-minute confirmation timeout restores the previous executable without automatically starting the incompatible revision. An explicit cancellation retains the previous binary for inspection. Successful reconnection releases the update lock so later upgrades can proceed independently.
